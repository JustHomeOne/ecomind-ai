# EcoMind AI

Панель экологического мониторинга одного ЖК по документу «Хакатон: идея 2.0».

**Сайт:** https://justhomeone.github.io/ecomind-ai/

## Запуск

Node.js 22.13+ (рекомендуется 24). Клиент не требует сборки. Для локальной серверной базы, проверок и упаковки Worker нужны инструменты разработки:

```sh
npm ci
npm run dev
```

Откройте http://127.0.0.1:4173. Проверки: `npm run check`.

## Возможности

- Адаптивная панель с 12 демонстрационными контейнерами, фильтрами и поиском.
- Настоящая карта Астаны по умолчанию: улицы и здания OpenStreetMap через MapLibre / OpenFreeMap, режим 2D/3D, масштабирование, обзор города и приближение к участку контейнеров.
- Ручные наблюдения; локальное сохранение; экспорт CSV.
- Анализ фото через совместимый сервер, настроенный в интерфейсе. Ключ Gemini никогда не передаётся в клиентский код.
- Отбор остановок по календарю, текущему заполнению или линейному сценарию; ближайший сосед + 2-opt на направленной дорожной матрице OSRM.
- Автомобильные маршруты по улицам Астаны, привязка остановок к проездам, длина и время из дорожного сервиса; экспорт CSV и GeoJSON.
- Матрица сравнения 3 × 2 по дорожным расстояниям, отдельно показывающая вклад порядка остановок.
- Текущий европейский/американский AQI, PM2.5, PM10 и открытый модельный прогноз из Open-Meteo / CAMS. Отдельное среднее 24 модельных часов для сравнения с суточными ориентирами ВОЗ.
- Чёрно-сине-белое оформление; пояснения «i» по наведению, фокусу и нажатию: смысл, метод расчёта, ориентиры и первоисточники.
- История наблюдений с фотографиями и графиком заполненности; результаты рейсов остаются в журнале.
- Импорт CSV / XLSX / XLS с проверкой обязательных полей, ошибок и повторяющихся ID; географический предпросмотр до сохранения. Можно заменить нетронутые демонстрационные площадки, сохранив реальные и ручные записи.
- Автопарк до 6 машин: вместимость, время смены, отдельные координаты баз. Обязательные остановки включаются независимо от порога; нераспределённые площадки и причины видны отдельно.
- Экран водителя: опубликованный порядок остановок фиксируется. «Вывезено» создаёт наблюдение 0%; отсутствие доступа и пропуск сохраняют прежнюю заполненность.
- Изолированный сценарий «День EcoMind», пять шагов; дневная и ночная темы.
- Поиск зарегистрированного адреса или площадки на карте, тип отходов, порог заполненности и свежесть наблюдений.
- Окраска карты по текущим внешним данным CAMS Global: европейский AQI, PM2.5 или PM10; легенда, время, обновление и сведения о ячейке по нажатию.
- Приватное командное пространство: D1, фото в R2, роли владельца / диспетчера / водителя / наблюдателя, приглашения и контроль версий при одновременном редактировании.

## Воздушная карта

Источник карты — почасовые измерения станций Казгидромета, подготовленные [AirData.kz](https://github.com/qazybekb/AirDatakz-OpenData). Файлы `astana/pm25.csv.gz` и `astana/pm10.csv.gz` обновляются автором раз в сутки; это не онлайн-поток. По состоянию на 21.10.2026 доступны четыре станции последнего часа. Браузер получает файлы напрямую с GitHub без ключа и разбирает gzip/CSV потоком; весь исторический CSV в памяти не хранится. Итог кэшируется на устройстве на час, кнопка обновления перечитывает источник.

Обработка EcoMind: только источник `kgmt`, координаты в пределах Астаны, валидные неотрицательные концентрации и замеры не старше 36 часов. Выбирается последний опубликованный общий час; показания других часов не смешиваются. Значения PM2.5 и PM10 остаются концентрациями в мкг/м³, общий AQI из них не вычисляется. На карте — отдельные станции и шесть административных районов. Станция относится к району через point-in-polygon с учётом внутренних колец и отдельных частей. Цвет и подпись района — арифметическое среднее доступных станций внутри его границ; число показаний, диапазон и время видны в карточке. Это сводка по станциям, а не замер всей территории. Районы без показаний остаются серыми с подписью «Нет замеров». Ошибки и пустые каналы не заменяются соседними, модельными или выдуманными значениями. Час замера, первичное значение и подготовка источника указаны в интерфейсе. Небольшое превышение PM2.5 над PM10 из источника сохраняется и поясняется как возможная погрешность каналов.

Границы шести районов — публичный слой [городского геопортала](https://gis.esaulet.kz/server/rest/services/Hosted/raiony/FeatureServer/0). Снимок получен 24.10.2026, исходный URL и SHA256 сохранены в `dist/astana-districts-data.js`; координаты округлены до 6 знаков. Принадлежность геопортала подтверждена [Управлением архитектуры Астаны](https://www.gov.kz/org/astana-saulet/press/news/details/324850?lang=ru). Дата актуализации геометрии источником не указана: слой справочный, дата получения не выдаётся за дату правового утверждения границ. Снимок обновляется вручную через `node scripts/update-districts.mjs`; при ошибке источника существующий файл не заменяется. Названия и границы доступны даже при недоступности замеров воздуха.

Набор данных распространяется по [CC BY-NC 4.0](https://github.com/qazybekb/AirDatakz-OpenData/blob/main/LICENSE), атрибуция: «Казгидромет · подготовка AirData.kz», указание обработки EcoMind и ссылка на лицензию есть на карте. Использование в этом учебном проекте некоммерческое. Для коммерческого использования нужна совместимая лицензия от правообладателя. Прогноз и AQI в карточках остаются отдельной моделью [Open-Meteo / CAMS](https://open-meteo.com/en/docs/air-quality-api), это прямо отмечено рядом с картой.

## Командная работа и локальный режим

[GitHub Pages](https://justhomeone.github.io/ecomind-ai/) — публичный клиент: записи на устройстве, фотографии в IndexedDB. [Приватная версия](https://ecomind-ai-city.brave-ridge-2075.chatgpt.site) — общий сервер и защищённые фотографии. В ней участник входит через ChatGPT, создаёт либо принимает приглашение в пространство. Владелец может перенести локальные записи; перед заменой показывается отдельное подтверждение. JSON-копия содержит данные и ссылки на фото, сами фотографии хранятся отдельно.

Общий режим использует `oai-authenticated-user-id` от платформы и проверяет членство для каждого запроса. Наблюдатель читает, водитель добавляет наблюдения и результаты остановок, диспетчер меняет площадки и рейсы, владелец управляет участниками. Приглашения действуют 7 дней; письма не отправляются. Доступ к самому приватному сайту предоставляется отдельно в настройках доступа Sites, затем приглашение в приложении определяет роль. Аудитория сайта при обновлении не расширяется.

У изменения есть базовая ревизия. При конфликте API возвращает 409 и требует обновить данные, исключая тихую перезапись чужой работы. При открытой странице общая база проверяется каждые 30 секунд. Рабочие настройки и тема остаются предпочтениями устройства.

Локальный сервер слушает только `127.0.0.1`. Он использует отдельную SQLite-базу и фотографии в игнорируемой `.local/`, с фиксированной тестовой учётной записью. Эти данные не попадают в Git и не публикуются. Схема D1 хранится в `db/schema.ts`, миграции сгенерированы Drizzle в `drizzle/` и применяются Sites при публикации.

## Автоматическая публикация

Каждый push в `main` запускает `.github/workflows/deploy-pages.yml`: проверка синтаксиса, тесты алгоритма и публикация `dist/` в GitHub Pages. Секреты для Pages не требуются. В Settings → Pages должен быть выбран источник **GitHub Actions**.

## Данные и ограничения

Исходные площадки, адреса, заполненность и темпы роста — демонстрационные. Они не являются результатами полевого пилота. В локальном режиме метаданные находятся в localStorage, фотографии — в IndexedDB. В командном режиме записи и фото сохраняются на сервере с проверкой доступа.

Карта использует реальные тайлы OSM с географией Астаны. Условная нарисованная схема удалена. Точки контейнеров, их адреса и начальные оценки заполненности выдуманные и явно отмечены прямо в блоках карты, показателей, реестра и расчётов. При недоступности картографического сервиса показывается ошибка и повторная загрузка, без замены города выдуманной схемой.

Для замены примеров реальными данными записи содержат `locationSource: 'real'` для подтверждённых площадок и `source: 'manual' | 'gemini' | 'sensor' | 'verified'` для наблюдений. Подпись о выдуманных данных автоматически исчезает только когда подтверждены и расположение, и наблюдения. Ручное изменение заполненности условного контейнера не подтверждает его координаты. Пока внешнего потока данных нет: реальные записи должен предоставить владелец пилота.

Расстояния и время движения берутся из автомобильного профиля OSRM / FOSSGIS по OpenStreetMap. Для выбора порядка используется направленная матрица дорожных расстояний; для карты — полная GeoJSON-геометрия, без прямых соединений через здания. Остановки привязываются к проезду в пределах 400 м; смещение от условной точки подписано в списке. Если дорожный сервис недоступен, показывается ошибка с повтором, без подмены пути прямыми линиями. Пустой рейс не вызывает сервис. Если новый порядок по полной геометрии оказался длиннее базового, сохраняется базовый.

Запросы к публичному демосервису сериализуются с интервалом не меньше 1,2 секунды, ответы кэшируются на 10 минут. Для массового использования нужен собственный или договорной роутер. Профиль учитывает дорожную сеть и автомобильные направления движения, но не текущие пробки, массу, габариты мусоровоза, реальный доступ во двор и обязательный график. Время рейса: движение из OSRM плюс настраиваемые 3 минуты на остановку. Расчёт не доказывает полевую экономию. Линейный сценарий заполнения не является обученной моделью. Матрица сравнивает один момент, без многодневного перерасчёта притока.

Данные воздуха модельные, не показания датчика во дворе. Прогноз получен от CAMS, а не модели EcoMind. Отсутствующие данные остаются отсутствующими. Европейский и американский AQI — разные шкалы. Нет доказанного влияния вывоза на воздух района.

У чисел подписаны период и источник ориентира. Хорошая категория EU AQI: 0–20, US AQI: 0–50; часовые хорошие диапазоны EEA: PM2.5 0–5 и PM10 0–15 мкг/м³. Рекомендации ВОЗ за 24 часа: PM2.5 15 и PM10 45 мкг/м³; годовые: 5 и 15 соответственно. Суточные ориентиры сопоставляются только с полным средним 24 последовательных модельных часов, без будущих часов и пропусков. Это ориентировочное сравнение модели, не проверка соблюдения нормативов. Пороги заполненности 75% и 90% — настройки пилота, а не официальные нормативы.

## Сервер анализа фото

В настройках можно указать URL собственного HTTPS FastAPI-сервера с:

- `GET /api/health` → `{ "gemini_configured": true }`;
- `POST /analyze` (multipart: `image`, `latitude`, `longitude`, заголовок `Accept: application/json`);
- ответ: `container_detected`, `contents_visible`, `fill_percentage` (0–100 или null), `fill_category`, `overflow_detected`, `confidence` (`low`, `medium`, `high`), `explanation`, `limitations`.

Сервер должен разрешать CORS только для нужного origin. API-ключ храните в серверной переменной окружения `GEMINI_API_KEY`, никогда в Git. Без сервера и ключа доступны ручные наблюдения и остальные модули.

## Дополнительное серверное развёртывание

Подготовлен Cloudflare Worker ESM в `worker/index.js`. `npm run build:worker` встраивает статические файлы в один Worker и проверяет артефакт. Развёртывание Sites использует `.openai/hosting.json`; GitHub Pages публикует только frontend, без серверного артефакта. Серверные тесты не выполняют внешних запросов.

Worker предоставляет `/api/health` и `/analyze` на том же домене. Без секретного `GEMINI_API_KEY` анализ недоступен; включение Gemini отложено по решению владельца. При необходимости задайте ключ через серверные секреты Sites, затем перевыпустите версию. Фото остаётся в памяти запроса и передаётся Google только при явном запуске анализа.

Сервер ограничивает размер запроса и проверяет MIME и сигнатуру файла. Полное декодирование изображения на Worker не выполняется: повреждённые файлы с корректной сигнатурой могут быть отклонены внешним сервисом. Результат проверяется по типам и границам; скрытое содержимое всегда даёт неизвестную заполненность.
